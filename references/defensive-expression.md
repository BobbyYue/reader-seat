# 防御性表达：检查与计数

在现有上下文审读中检查当前交付文字，不增加审稿人或轮次。记录留在内部，不把检查说明加进正文。

## 自动定位的词与句式

以下表达进入候选检查，不直接判为多余，也不自动删改。识别由 `scripts/defensive_expression.py` 执行，继续进入原有上下文审读。

| 检查对象 | 包含的词与句式 |
|---|---|
| 否定与纠偏 | 不是……而是……、而不是、并不是、并非、不是说、更准确地说 |
| 推断与证据限制 | 不能推出、不能据此、不能仅凭、不能只凭、不能只看、不能仅靠、不能简单、不能说、不能断言、不能断定、不能认定、不能视为、不能当作、不能当做 |
| 证明与说明 | 不足以说明、不足以证明、只能说明、只能证明、不证明、无法说明、无法证明、不能说明、不能证明 |
| 范围、等同与不确定性 | 不代表、不等于、不等同于、不意味着、不一定、未必、不必然、不完全、不构成 |
| 能力、承诺与状态 | 不能、不能直接、不能把、还不能、尚不能、不能保证、不能确定、不能确认、不能承诺、不保证 |

原有“没有证据”“未发现”“尚未”“仅供参考”“因人而异”等及英文信号继续保留。成对纠偏识别实际的“不是A，而是B”，兼容省略号写法，遇到句末、换行或分号停止跨段匹配。同一位置的长短词重叠时优先记录完整词；同一句有多个命中仍先合为一个待审句，不把关键词数当成C或D。不同位置的重复表达逐处保留。

例如“这只能说明本轮已完成，无法证明后续不会出错”会进入审读；是否多余取决于读者是否需要这个限制。“尚不能确认恢复时间”“不能承诺周五交付”可能是必要的不确定性或承诺边界；文学人物的“未必”“并不是”也可能承担语气、矛盾或自辩功能，应结合上下文保留。

## 写前、写中、写后

- 写前：沿用读者任务、来源和必要限制，确定读者实际需要澄清什么；文学场景辨认作者说明、引文和人物声音。
- 写中：完成一个段落、场景或消息后，检查无关纠偏、重复设限、空泛免责。比较原句、删除版和同样准确的直接写法；有实际收益才改。
- 写后：现有 `context_review` 必须完成 `defensive_expression`，同时看开头、结论、图注、脚注和跨段重复。程序复算位置和计数；原文改动后重新检查当前版本。

## 计数口径

| 项目 | 计算与用途 |
|---|---|
| C：候选处数 | 审读记录中的独立表达数。程序先按句定位，评审可按实际独立判断拆分或合并，并补充无关键词的问题。每个词命中不单独算一处。 |
| D：确认多余处数 | `classification=excess` 的独立表达数。每处须有具体阅读损失及删留、直接改写对照。 |
| R：多余表达占比 | 多余片段跨度取并集，NFC规范化后计非空白Unicode字符，除以同范围可见非空白字符数。分子、分母保留整数。 |
| 待确认 | 单列 `pending`，有待确认时R记未测，D仅表示已确认部分；不宣称全篇零问题。 |

当前稿的确认问题应全部处理，正式完成时D＝0、待确认＝0。它是编辑完成条件，不是“不能”“不是”等词归零，也没有统一比例及格线。待确认或确认多余可进入既有修订、草稿路径，不能被记成正式通过。

必要限定可以收进结论：“在这12位受访者中，A更受欢迎”。实验里的“未发现显著差异”、安全禁令和确有作用的人物自辩应保留。合成例子：“我不是怕她，我只是没想好怎么开口”可能表现嘴硬，需从上下文说明作用。来源原句保持原样，评审作者添加的框架；不要为了降低数字改成更确定的结论。

## 记录与执行

`context_value.py prepare` 自动附带模板，`check` 强制核验并返回计数。长文已有质量测量中的 `defensive_expression` 先报候选和未测的D/R，语义确认由同轮上下文审读完成。Hit Send对推荐版与每个备选分别检查，临时消息与记录按原隐私规则清理。

每条保留 `issue_id`、原文跨度、上下文、删除结果、直接改写、具体影响、需保护的含义、前文是否已讲过及分类。拆并后保留所有自动信号的定位覆盖；新增无关键词项目使用同样字段。与冗长表达重复命中时复用 `issue_id`，不把不同指标的问题数直接相加。原文、引文、人物台词依其用途分别判断，不把人物声音磨成客观说明。

`excess_spans` 必须落在该表达内；无法可靠划定时写 `unmeasured_reason`，保留D而将R记未测。同一位置的多重命中合并；相同内容出现在不同位置逐处检查，独立入口可能需要重复限定。把文字移入脚注或折叠区仍须检查。

可单独排错或查看修改前计数：

```text
python3 scripts/defensive_expression.py prepare --text visible.txt --review defensive.json --profile functional
python3 scripts/defensive_expression.py inspect --text visible.txt --review defensive.json --profile functional
python3 scripts/defensive_expression.py check --text visible.txt --review defensive.json --profile functional
```

`inspect`允许记录D大于0的当前问题；`check`要求问题处理完毕。两者都绑定实际文本。文学用 `literary`；原上下文评审支持的 `spoken` 和 `teaching` 仍可用。局部输入只报告该范围，不能据此给整篇作出零问题结论。

程序验证记录、跨度、版本和算术；语义判断仍由现有评审承担。测试同时覆盖删掉多余免责和保住必要限定，不能用D下降证明读者体验已提升。Skill没有安装宿主全局拦截器。

维护时使用[成对案例](../evals/defensive-expression-cases.json)，只把输入、语境和写作类型交给执行者，预期留给评阅者；分别记录漏检、误删、含义漂移及未运行项。
