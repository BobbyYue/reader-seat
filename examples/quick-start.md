# Reader's Seat 使用示例

## 最小写法

你不需要记住固定模板。把材料交给 Agent，再说明读者和目标即可：

```text
使用 $reader-seat 整理这份材料。
读者是第一次接触该项目的管理者，希望他能判断当前进展、主要风险和下一步。
```

## 更稳定的写法

当文档重要、材料复杂或读者明确时，补充四项信息：

```text
材料：原文、数据、来源或文件
读者：角色、专业程度、已有背景
目标：需要理解、判断或完成什么
格式：HTML、飞书、Word、Markdown、纯文本等
```

## 新闻和行业资料

```text
使用 $reader-seat 总结这些行业动态，输出 Markdown。
读者是产品和战略团队。请区分官方确认、媒体报道和未证实消息，
标清事件时间，不要强行加入行动建议。
```

## 技术方案

```text
使用 $reader-seat 重构这份技术方案，输出为评审文档。
读者需要判断约束、备选方案、取舍、迁移风险和回滚条件。
缺少的信息请明确标出，不要替作者选择方案。
```

## 产品介绍

```text
使用 $reader-seat 重写这份产品介绍。
读者是潜在试用团队。请说清楚适用对象、要解决的问题、已提供能力、
发布范围和暂时不支持的内容，删除没有证据的“领先”“高效”等表述。
```

## 工作汇报和绩效总结

```text
使用 $reader-seat 把这些周报、项目文档和复盘捋成一版半年工作总结。
读者是管理者。区分活动、交付和结果；没有收入、用户或效率数据的地方，
不要把活动量包装成业务影响。
```

## 数据分析

```text
使用 $reader-seat 重写分析报告，输出自包含 HTML。
读者需要知道指标发生了什么变化、证据是否可信、哪些解释仍未验证，
以及下一步应该补充什么数据。保留口径、幅度、分母、周期和不确定性。
```

## SOP 和帮助文档

```text
使用 $reader-seat 把现有步骤整理成新同事可以执行的 SOP。
保留已知操作顺序，补齐前置条件、成功信号、异常分支、恢复和升级路径；
材料中没有的权限、命令和负责人标为待确认。
```

## 指定输出语言

默认情况下，输出沿用原材料的主要语言，而不是提示词语言。如果需要翻译，请直接说明：

```text
使用 $reader-seat 将这份英文技术方案整理成中文评审稿。
代码、命令、API 名称和产品名保留原文。
```

## 只诊断，不改写

```text
使用 $reader-seat 诊断这份报告是否方便目标读者形成正确判断。
只列出事实、证据、结构和行动边界方面的实质问题，并给出最小修正建议；
不要直接重写全文。
```
